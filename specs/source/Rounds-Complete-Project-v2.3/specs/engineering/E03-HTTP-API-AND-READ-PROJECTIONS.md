## Contract artifacts

[OpenAPI](../contracts/openapi.json) and [command catalogue](../contracts/COMMANDS.md) define 131 typed command endpoints (including the disabled partial-pickup command), 26 purpose-specific queries and batched location ingest. URL host is a documentation placeholder. This is a review contract, not a deployed API. Auth login/refresh/OTP uses the selected Auth provider boundary; object storage upload uses authorized upload capabilities; SDK voice/navigation use their adapters. They are not falsely represented as implemented Rounds endpoints.

## Command envelope

All commands carry command_id UUID, server-validated tenant/city context, client occurred_at, expected_versions array and typed payload. Actor identity comes from authenticated credentials, never payload. Global driver self commands may have null tenant context; tenant actions require the current tenant and permission. Client time is evidence only; deadlines use server time. Create commands may have an empty expected-version list but must lock/check parent scope and uniqueness. Every mutation of existing roots supplies expected versions for all affected roots; server determines the authoritative dependency set rather than trusting an incomplete client list.

The same command ID with different payload hash returns IDEMPOTENCY_CONFLICT. Repeated same command returns original sanitized result. Responses distinguish committed, queued, in_progress and rejected; HTTP 202 means durable processing intent, not completed delivery. CommandStatus is scoped to original actor/authorized service, and cannot be used to discover another tenant's result. Long-running parsing/planning/export returns operation ID and explicit per-child outcomes where applicable.

## Errors and conditional validation

Use stable machine codes and localized message keys: VALIDATION_FAILED, NOT_AUTHORIZED, STALE_VERSION, IDEMPOTENCY_CONFLICT, SLOT_FULL, SLOT_CLOSED, CUTOFF_PASSED, HOLD_EXPIRED, PHYSICAL_INCOMPATIBILITY, DRIVER_CONFLICT, CLAIM_TAKEN, OFFER_EXPIRED, OFFER_WITHDRAWN, CONSENT_REQUIRED, CUSTODY_MISMATCH, EVIDENCE_PENDING, SOURCE_STALE, PROVIDER_UNAVAILABLE and UNKNOWN_RESULT. Return permitted current version/action hints; never leak competing merchant detail in DRIVER_CONFLICT. 429 includes retry guidance; 503 may follow an unknown request outcome, so reconcile original attempt before making a new command.

Typed shape validation is necessary but insufficient. Rules such as destination required for destination change, all selected IDs same manifest, at least one nonempty message text/attachment, actual signature receiver, slot end after start, finite busy ranges and verified evidence ownership are domain validation. Reject unknown fields to prevent accidental silent compatibility assumptions. Version schemas deliberately; old supported clients receive explicit UPGRADE_REQUIRED when an operation cannot be safely interpreted.

## Transport details

ADR-T08's isolated ResolveIssue POST requires verified bearer and active issues.decide capability in the explicit tenant/city, not a Driver device session. Its bounded64KiB request selects only issue/version. GET CommandStatus without X-Rounds-Device-Session routes to this Operations boundary and may retrieve only the submitting actor's ResolveIssue receipt under current city capability and recorded original job association. Presence/absence of that header is not authority; the Driver branch still independently enforces original device/job ownership and cannot accept Operations results as physical receipts. Other actors' receipts remain unavailable even to same-city colleagues. Dispatch controls and installed phone activation remain separate work.

TLS only. Authenticate bearer session for actor and separate scoped credentials for integrations. Customer tracking uses its dedicated token, not a guessed tenant ID; the OpenAPI tracking query explicitly uses its own TrackingToken security scheme. Upload URLs are expiring, purpose-bound and never persisted in command receipt/event payload. Server limits body/media/batch size and validates country-specific phone/address rules through typed normalization. API origin/CORS and request rate controls do not replace permission checks.

The isolated W01.2 boundary retains the approved paths. ConfirmPickup requires an authenticated expiring X-Rounds-Device-Session capability in addition to its bearer; it stays outside the immutable command envelope. GetCommandStatus uses entity_id and original tenant_id/city_id filters, with the same Driver credential checks for pickup. No Round/assignment supplied by the caller authorizes status: the server uses recorded original receipt job IDs and current access. A missing result returns404 NOT_FOUND, missing authenticated identity401, denied scope403, invalid input400, unprovable old scope422 UPGRADE_REQUIRED, rate limit429 with Retry-After, dependency/uncertain result503. Stored business rejection is exposed as Error at its mapped4xx on POST and as the original rejected CommandResult in the200 status projection. Do not mark a4xx Error as a committed result.

ADR-A01 bounds uncompressed JSON to1MiB before Node buffering and Web Request parsing, with10s Node body deadline, explicit origin/preflight rules, server trace IDs and no-store responses. ADR-A02 adds POST /v1/auth/driver-device/session and /v1/auth/driver-device/revoke with4KiB bodies and exact DriverDeviceSession/Revoke request/result schemas. The verified bearer plus installation secret resolve self-owned device identity; no body actor, tenant, device ID or epoch is accepted. New registration/first revoke append a private typed security audit in the same transaction; refresh does not emit a business event. Unknown outcome retries use the unchanged installation secret. All four paths require isolated-local runtime opt-in; legacy paths are unchanged. Native credential persistence, encrypted-client upgrade and real configured Auth remain required integration work.

## Contract generation and compatibility

GetBoard explicitly selects view=pickup_issues (ADR-Q05) with tenant_id, city_id and service_date, optionally display=labels. OperationsPickupIssuesQueryResult is separate from the unchanged default BoardQueryResult. The isolated runtime supports the finite pickup_issues and delivery_board views: cursor, limit, entity_id, duplicate/unknown fields, invalid dates and other display values reject; unsupported views fail closed. display=labels is pickup_issues-only and display=now is delivery_board-only; neither is accepted by CommandStatus or commands. At most200 reports and64KiB, ordered reported_at/id; excess rejects FEATURE_NOT_ENABLED rather than truncating or implying an empty board. Full filter-bound cursor paging and complete board projection remain separate work.

The separate view=delivery_board (ADR-Q06) returns OperationsDeliveryBoardQueryResult under board.read, independently of issues.decide. It includes all unarchived orders for the exact selected city/date even without reports or inbound receipts. One repeatable-read snapshot binds authorized workspace/city labels and order facts;200 rows/1MiB bounds reject excess. Preserve raw state axes, actual nullable destination source, unique current-manifest planning references and explicit null/ambiguous labels. Never claim entrance confirmation, readiness, GPS or complete fleet from these fields. Version/window/timezone and contradictory planning source failures reject SOURCE_STALE. Same-tenant cross-city joins, private contact/notes and speculative labels are prohibited. No new query/command, database/local-storage migration or changed earlier response is introduced.

ADR-Q07: display=now adds data.now with current_service_date derived from the transaction timestamp in the authorized city's timezone, and one entry per returned delivery ID. Omission retains the old exact shape. Each entry is a server-derived bucket/reason, never a client-inferred physical state or allowed command. Read scoped unresolved issue existence (including a Round-only issue for its current planned orders), current-manifest whole-unit state/collection timestamp and failed/handed-over attempts, and current assignment cannot_comply. Do not expose issue detail/IDs, driver/Auth IDs, notes, contacts or assets under board.read. Report review/decisions still need issues.decide. Missing or ambiguous current-unit/assignment facts never become ready; contradictory duplicate source associations reject SOURCE_STALE.

Category precedence: unresolved issues, disputed evidence or unresolved/historical partial outcome → Action; otherwise delivered/returned/cancelled/rescheduled outcome → Done with the actual outcome label (never all labelled Delivered). An open failed stop/attempt or declined assignment → Action. A current whole unit actually collected with a timestamp → On road (handed_over reason if its current attempt says so; this does not claim live motion or server completion). Before collection, review-needed address/readiness, held readiness, blocking departure/receipt/discrepancy/preparation → Action; draft or missing current manifest/unit/stored destination → planned, available in Show all/Plan, not Ready. Ready requires open current whole unit, ready readiness/preparation, stored destination and no non-ready current Round gate; assigned planned work is labelled Ready for pickup but is still subject to release/arrival/current command guards. Without planning it is Ready to assign. No receipt or custody is synthesized; raw fields remain independently visible. Active issue takes precedence over a stale terminal flag for investigation. Resolved/archived issues and obsolete attempts do not manufacture Action.

Now uses the server's current city day, not the workstation clock or a selected future Plan date. Selecting Now from a future Plan date requests a fresh reader for that day; pending/failed reads cannot relabel the old date as Now. Search and brand predicates are shared by category counts and rows, with each delivery counted once. planned entries remain accessible through the source Show all deliveries control. Actions not yet wired to an authorized handler stay disabled or read-only; tab classification is not command authorization.

Without display, preserve the existing exact issue shape for strict earlier clients. With display=labels each issue includes exactly five nullable fields: delivery_reference, recipient_name, destination_address, pickup_site_name and reported_driver_name. The first, second, fourth and fifth are bounded to200 Unicode scalars; address is bounded to2000. Values are current same-scope display facts, not original snapshots, identity matching keys or command inputs. Preserve valid strings without trimming or truncation. Missing/blank/overlong data, archived associations and ambiguous recipient contacts return null. Select only the sole unarchived recipient, not buyer/alternate contacts; join the reporting driver's original principal under a current team relationship, not the new assignee. Round-only reports return null delivery fields and changed original job scope suppresses every label. No contacts' secret/masked channels, private notes, Auth identifiers or media are selected. A label-enabled browser rejects a response missing display instead of inventing labels. Labels are never added to the recovery journal or used to rebase a command. No database/local-storage migration or expanded grants are required.

The view includes original ReportIssue-bound records only, including Round-only waiting without invented delivery IDs. Authorization uses current verified principal, active tenant/city membership and issues.decide. Each read runs one restricted repeatable-read transaction with no domain writes. Archived or foreign records and unbound legacy/sample exceptions never become new command targets. Shared decision-job predicates produce wait/escalate only when the original assignment/job is still eligible. Changed work remains visible in the authorized city with original IDs and ORIGINAL_SCOPE_UNAVAILABLE plus no actions; resolved issues and the200-decision limit have explicit disabled reasons. Commands always recheck all predicates/version under locks. Current immutable instruction is selected by supersedes_id, not time; broken chains fail SOURCE_STALE.

The staged Operations browser adapter validates static generated schemas without runtime code compilation, bounds response bytes, pins principal/session epoch/tenant/city/date and omits Driver credentials. Refresh failure preserves labelled last-known data with actions disabled; authorization/account changes clear private memory. An explicit new reply freezes command ID/time/version/text. ADR-Q05's optional login/tab-scoped journal saves draft and exact attempt before POST; restore requires a fresh authorized Board read and never automatically sends. Retry reads own CommandStatus first, and only a typed NOT_FOUND permits identical-byte resend. No fresh version or command ID is synthesized on retry. Successful commit fetches a post-commit projection rather than accepting a read started before the POST; persisted version floors reject regressed reads. Storage denial/quota/corruption/conflict blocks new sends without overwriting other work. This is not a cross-tab/background queue, full Phase39 board or installed phone. The default-off bounded host requests the label extension; verified login lifetime, dirty-close review, login-wide erasure, actual browser reload/storage and source presentation remain activation requirements. Command/status contracts are unchanged.

GetDriverRound explicitly selects view=execution (ADR-Q02), view=pickup (ADR-Q03) or view=pickup_issue (ADR-Q04). entity_id is the Round, with tenant_id/city_id and X-Rounds-Device-Session required for all three. pickup_issue additionally requires issue_id from a committed original ReportIssue receipt; other views reject this extra parameter. DriverRoundExecutionQueryResult, DriverRoundPickupQueryResult and DriverPickupIssueQueryResult are separate from the unchanged default/full DriverRoundQueryResult. The isolated runtime serves these finite views, fails closed for unsupported shapes/configuration, and performs no domain writes. Full-view discovery and R3/R4 queries remain separate. Query responses are not committed predecessors and cannot refresh a frozen observation's expected versions.

pickup_issue returns one original actor-owned pre-pickup report with its unchanged acknowledged assignment ID/version and current tenant/city/device access. It requires no refreshed execution/policy projection and creates no capture context. Resolve by supersedes_id, not timestamp. Missing/foreign/legacy-unbound/reassigned reports deny without disclosing existence; corrupt/forked/inconsistent decisions return SOURCE_STALE. Partial-pickup decisions are disabled. These are facts, not allowed-actions: even action=ready cannot bypass actual collection/release predicates. No private report detail, decision actor, customer agreement, asset or provider token is returned. Existing execution clients receive no new fields. Display names do not enter accepted_scope_hash or frozen commands. No packages means an empty packages array, not quantity-derived parcels; explicit package contents must cover the manifest exactly in integer ten-thousandths. Missing/ambiguous recipient or invalid display metadata returns SOURCE_STALE without partial data; bad contents return MANIFEST_MISMATCH. Work discovery, command submission and the non-package UI state remain separate work. No SQL/local schema migration is needed.

Generate TypeScript and Dart models from reviewed schemas in CI. Domain state codes, error codes and integer money meanings must match across apps. Include canonical valid and invalid examples per command, schema/reference checks and contract replay tests. Query/event schemas are defined as minimal authorized projections; implementation may add fields only with version compatibility and privacy review. No client should depend on SQL row shape or generic select-all endpoints.

## Typed policy consistency

SavePolicy validates `policy_kind == policy.kind`, schema version and domain-specific scope. The 16 discriminated policy families include map and weather, with the same kind value in SavePolicy, stored policy and schema. Slot date overrides validate against slot-rule timing fields; role grants and vehicle capacities use their dedicated relational command contracts. An enabled AI policy never grants permission to approve its own address correction. Provider adapter webhooks are isolated integration entry points under E07/P12; their provider-specific signature envelopes are finalized with provider selection and are not generic authenticated user commands.
