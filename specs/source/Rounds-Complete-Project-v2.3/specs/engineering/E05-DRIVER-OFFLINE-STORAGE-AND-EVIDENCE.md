## Durable local observations before commands

The driver caches authorized assignment_id/version, accepted scope hash, unit IDs and stop IDs while online. A job never seen/authorized online is not invented offline. The local encrypted store keeps immutable observations with observation_id, principal/device/session, original observed_at, assignment fence, payload, evidence references and predecessor observation IDs.

An observation is not yet a final API command. command_id is allocated and stored when materializing it. Resolve observation_bindings only from authenticated committed predecessor results/GetCommandStatus. Freeze payload bytes, expected_versions and request hash atomically with the queued command. Once queued/sent, those bytes never change; retries use the same command ID/hash.

For D03/D04, ADR-S08 stores the first authorized pickup display, original context, actual arrival ID and explicit parcel selections in work_cache/pickup_collection_v1 (principal/assignment revision/pickup key, bounded256KiB). The confirmation UUID is reserved once; first observed_at is durably committed before observation insertion so crash recovery cannot create a second pickup. All actual parcels must be checked and quantities remain the full manifest. Selection/intent changes require current original scope; new arrivals or changed package identities cannot silently reset old work. Recovery reads that encrypted record under the same authenticated owner, without implementing offline unlock or adopting legacy rows. The shared-view controller uses existing materialization/status recovery; only a committed receipt navigates to success. Missing recovery artwork remains a host integration gate, not permission to add a new board.

## Binding contract

ADR-S06/S07 implement the first local linear arrival→pickup→dropoff arrival→handoff→proof→completion connection. Explicit observed_payload.command_payload carries action fields only; derive stop/Round/attempt/handoff/policy/verified asset and arrival identities from original context/committed receipts. Atomically persist canonical request/hash/link/roots/dependencies/pointers. Internal photo reservation/verification uses existing encrypted work_cache/upload_sessions and pending_commands, without a schema migration or new physical observation. Generic old captures and branched/multi-candidate/signature work remain unsupported rather than guessed.

| Successor | Required predecessor result binding |
| --- | --- |
| Pre-pickup ReportIssue | Original Round/selected delivery versions; optionally this pickup's committed arrival/earlier issue changed roots only; no fabricated arrival or receipt |
| Dropoff arrival | Known stop ID; current stop version from successful pickup/navigation predecessor if it changed that stop |
| RecordHandoff | ConfirmPickup.data.attempts item selected by fulfillment_unit_id → attempt_id; own successful arrival receipt → latest attempt/stop version |
| SubmitProof | RecordHandoff.data.handoff_id and attempt_id; VerifyAsset result IDs for uploaded evidence |
| CompleteDelivery | SubmitProof.data.resource.id → proof_submission_id; latest own predecessor versions for attempt/proof |

Select pickup attempt by unit identity, never array position. observation_bindings stores predecessor ID, exact result JSON pointer, target payload pointer, resolved value and receipt command ID. execution_fences stores the originally authorized assignment. For successors, merge only versions changed by that observation chain; do not overwrite unrelated expected versions or update the assignment fence from a fresh fetch.

ADR-S09 extends this store with immutable issue observations carrying the original authorized pickup execution snapshot and explicit package/wait action. Validate delivery/unit/manifest/stop joins and exact optional quantities at capture and materialization. New query contexts contain all actual delivery versions; old snapshots with none remain readable and cannot acquire them from refresh. A selected-order report without its original version requires recovery, not a guessed value. ReportIssue uses the existing sender/status pipeline and accepts only one open issue plus actual selected-root changes. Waiting has zero changes; already-held roots may stay unchanged. Damaged/wrong media follows the purpose-bound path below. Mutable G03 staging now follows ADR-S09: editable encrypted form/camera candidates precede immutable submission. ADR-T08 supplies Operations wait/escalate; physical decisions, source visual comparison, approved recovery presentation and installed route activation remain separate required work. Preserve all old encrypted data and command bytes.

The staged G03 controller/route connects a committed original report (including reopen) to ADR-Q04 before requiring any further user input. Enter the host recovery destination immediately with a loading state; a slow query must not delay navigation or resend a committed report. Explicit Refresh is read-only and coalesces taps. Keep report-submit errors separate from reply-read errors. Preserve exact actual instruction text and as_of, mark a previous in-memory result last-known while loading/failed, and reject an issue version older than already observed. A failed first read is unavailable, not an empty decision. Pin the original Auth lease before scheduling; discard late data after lock, same/different-account sign-in or disposal. On reopen, read the encrypted committed receipt and query anew; this adapter adds no durable reply cache, offline unlock, observation/schema migration or ready/continue authority. The host owns the controller lifetime and approved waiting/contact visuals.

## Rejection, unknown response and changed assignment

If response is lost, query GetCommandStatus for the original command ID; never mint another command for the same observation. Block successors until committed result/identity is known. Rejected or retained predecessor does not authorize later commands. Keep captures and dependency chain; upload genuine assets and use RetainOfflineObservations with original assignment/device/observed timestamps and reason. The server verifies historic ownership and stores the chain under an incident without mutating current work.

ExecutionFence is required for pickup, arrival, handoff, proof, completion and ReportIssue. A current assignment/version mismatch is retained/reviewed rather than bypassed by refreshing expected versions. ADR-S06 marks an unsent invalidated command needs_review; it still probes an already uncertain original command for an authenticated result, and never requeues after404 under invalidated scope. This local disposition is not the unimplemented RetainOfflineObservations incident acknowledgment. Same driver legitimately reassigned under a new agreement is still a new fence. Retained observation acknowledgment is not delivered/completed.

## Photo upload and verification

ADR-M04's server path accepts issue_photo with required original pickup_context; purpose_entity_id names the selected delivery, not a handoff or invented issue. The immutable report observation/fence/time and pickup/unit/manifest must match the later ReportIssue. ADR-S09 specifies original-report camera intent and purpose-aware transfer using the same encrypted capture/uploader. Damaged/wrong require one matching saved local asset; no caller supplies remote asset identity. Verified receipt identity is bound atomically into the later report command. A pre-arrival report has no fabricated predecessor: receipt bindings live in its encrypted transfer record with real command dependencies, without changing the schema's no-self-dependency rule. G03 form/preview staging uses pickup_issue_form_v1 and exact selected capture provenance in the existing camera intent; latest durable note and selected capture time freeze only at explicit submission, before observation/command creation. Empty optional details are omitted, nonempty details remain exact. Cancelled retakes preserve previous selection; successful retakes retain older bytes. Failed edit persistence blocks submission. Actual host recovery, OS/provider tests and activation remain separate. Preserve prior native schemas, captures and request bytes.

ADR-S07 implements one saved delivery photo with a committed original handoff. Persist only identity-only ReserveAsset receipts; obtain fresh capabilities in memory for raw signed PUT to an explicitly configured HTTPS origin. Refuse redirects, userinfo/fragments, separate tokens, unsupported methods and unrelated asset IDs. Never send app credentials to storage or persist signed URLs. Preserve encrypted local bytes throughout. Before PUT persist uncertainty; after a lost response attempt server verification first. Only authenticated missing verification/status permits reupload with the same command IDs and a fresh capability. Local_assets.saved means local integrity; transfer verified requires the actual VerifyAsset receipt, not upload progress.

Proof evidence references local_asset_id and binds the verified remote asset only after the transfer. Location binds this stop's own arrival observation; attempt/handoff/policy/proof IDs derive from original-chain receipts. Separate SubmitProof and CompleteDelivery acknowledgments retain truthful pending/completed states. Signature/general/resumable media, multiple photos/candidates, continuing multi-order/branching, configured providers, full UI and mobile/offline acceptance remain open. Existing observation/photo/Driver5 bytes are never rewritten or deleted.

## Evidence persistence

ADR-S04 implements storage without changing the reference schema. ADR-Q02's registered-device GetDriverRound execution reader now supplies a bounded, exact-shape context through the original lifecycle lease; the store freezes it in work_cache and execution_fences. Refresh keeps the first expected versions/time, invalidates obsolete assignment revisions and fails on same-revision scope conflicts. An observation freezes the original context, device/session, action payload, ordered predecessors and planned evidence metadata. Commit its intent and capturing asset row in one SQLCipher transaction, then use the existing staged encryption sequence. A missing or interrupted photo is never a saved observation; restart derives pending/recovery state from the referenced asset and verifies saved bytes. Duplicate observation IDs require exact original content and return the same record; later assignment refresh must never replace the embedded fence. No current legacy stop/cache row is converted into this authority. Full work discovery/UI, camera lifecycle, command binding/materialization and sender remain separate required connections.

Capture private encrypted file and metadata before showing safely saved. ADR-S05 now records camera_capture_intent_v1 before opening the shared native camera, separately from local_observations. Keep background locks; reverify the same account on return, reject changed device epoch/account and preserve original assignment even if reassigned during capture. Finish only that authorized original intent into encrypted evidence; a pending intent has no photo/command/verified outcome. Confirmed cancellation and failed retake leave the prior good photo unchanged. Exact-byte completion retry recovers lost acknowledgment; unresolved plugin results remain explicitly awaiting recovery and never use automatic lost-data adoption. Full screen/work discovery, temporary camera-source protection/recovery, offline continuation and actual OS acceptance remain open.

Reconcile crash between file and DB write through staged paths/checksums/orphan scanning. ADR-S02 pins the new SQLCipher working store and authenticated file format. Keystore reference is not encryption itself; native file protection/backup/restore and actual mobile verification remain implementation gates. TUS/resumable upload reserves purpose/size/hash; uploaded bytes must be verified before proof satisfies policy. ADR-M02 implements a bounded own-team server seam: reserve against the actual handoff, preserve immutable actor/assignment/attempt/policy binding, verify actual JPEG/PNG bytes and seal a private immutable copy before returning verified. Signing/read/write IO occurs outside transactions and authorization is rechecked afterward. Provider integration, resumable transport and the native uploader/materializer remain unconnected; isolated storage doubles are not a configured Supabase upload.

The current encrypted store is opt-in and separate from Driver5: the preservation path never opens the old database for writing. A private verified-subject/environment/principal namespace has independent database/media keys, persisted before database creation. Missing/corrupt keys, unknown schema, unreadable database or missing DB with existing evidence require recovery without replacement. One filesystem writer lock covers isolates/processes. Sign-out/account switch/revocation closes the store and invalidates old handles without deleting bytes. ADR-S03 now connects main/controller/DriverApi through an off-by-default Android debug checkpoint: archive before legacy startup, authenticated session recovery before queue access, synchronous sign-out lock, HTTP401/403 denial lock and conservative Auth-expiry timer. It does not move legacy rows/photos into the new account store or redirect commands/camera. Local evidence access is not re-authorized by a new job or refreshed assignment.

For new photo evidence persist capturing metadata, encrypt with authenticated metadata, flush staged ciphertext, rename and flush its directory, verify decryption/hash, then commit saved. Retry identical capture ID/content without a second record; changed content/metadata under that ID conflicts. Restart may promote only a verified staged/final file from capturing to saved; missing/tampered/ambiguous files enter recovery. Unreferenced files remain counted and retained. No delete/verified/uploaded/completed operation is supplied by this storage increment.

Retain original observation time separately from server receipt time. Upload retries only missing bytes/assets. Do not delete required local evidence until verified server receipt and retention policy allow it. Another principal cannot inspect/sync the previous principal’s data. App kill/restart preserves bindings, frozen commands and uncertain results.

Device credentials follow ADR-A02: verified Auth subject scoped by origins, installation record bound to returned principal/device, no destructive storage-error reset, stable identity through retry/revocation and no disk-cached capability. Sign-out invalidates in-flight results without deleting evidence. Mock-backed adapter tests are separate from actual Keychain/Keystore, backup/restore and kill/restart tests.

Android ordinary secure-store writes require the ADR-A02 disk-commit barrier before sending registration. Test key/config/data commit order, each failed commit, missing platform method and no registration after failed persistence; then verify actual process-kill/full-disk/restore behavior on device. Awaited asynchronous SharedPreferences.apply() plus read-back alone is not durability evidence.

## Local schema and acceptance

DRIVER-LOCAL-SCHEMA.sql uses user_version 2 and 14 tables, including observation_bindings and execution_fences. The clean reference schema is executable SQLite; it is not an implemented Flutter encryption/recovery layer. Journey J04 specifies disconnect before pickup, full delivery, restart, response loss and intervening reassignment without manual ID repair.

The existing-data migration starts from actual Driver schema5, not the clean reference. First snapshot all seven old application tables read-only; preserve exact row identity and external media. Unknown versions/tables fail closed without repair, deletion or creating a missing database. Unproven per-record ownership/fences require recovery; a current login cannot fill them or gain access by copying ambiguous old records into its own new encrypted store. Test pending/sending/unknown/uploading rows, raw JSON whitespace, offsets, multi-page inventory and byte-identical DB/photos after repeated inspection. Empty queues do not clear orphan-file/encryption/conversion gates. A preflight report or a tested fresh encrypted store is not an importer or migration success.

The ADR-U02 preservation step copies the exact schema5 database bytes and files from the six repository-owned media roots into a separate SQLCipher recovery archive, not account_context/local_assets or new commands. Preserve allowlisted raw draft preference values (including malformed JSON), row hashes, original file paths/hash/size and relationship diagnostics inside the encrypted manifest. No current principal is accepted and no normal-account plaintext read/export API exists. Unknown owners/fences remain unassigned; source credentials/namespaces remain untouched. Known draft preferences are read through a reloading adapter, never cleanup-capable restore helpers.

No legacy writer may run during archive capture. The bounded checkpoint starts from cold main before controller/cache/timers/UI construction; controller and HarnessDatabase entry points claim legacy use before awaiting IO. Its isolate-local startup guard refuses late/concurrent preparation and blocks legacy startup after failure. This is not a pause/resume mechanism for an already-running old client, another process or a future background isolate. The native runtime lock still excludes cooperating v2.3 owners. The Android adapter reads exact database/support paths and allowlisted drafts, rejects missing/unknown schema5, journals and nonzero source issues, and aborts without a fallback controller. It is not a fresh-install path. A successful point-in-time archive remains unassigned; legacy writes after startup are not mirrored/imported and no cutover is authorized.

Pending journal/WAL/SHM requires recovery without alteration. Bound inventory and streaming copies; refuse unexpected schemas, source changes, wrong/missing keys and malformed archives. Missing/outside-root/symlink references are recorded without reading unsafe targets. Orphans and .pending files are copied when safely readable, never adopted as completed proof. Commit copying manifest → atomic per-file encrypted chunk transactions → verify all archived bytes → rescan original DB/drafts/media → sealed preservation receipt. Lost acknowledgment retries the exact snapshot; incomplete and superseded snapshots remain retained. A sealed receipt may include explicit missing/unsafe-source issues and always means quarantined_unassigned, never full migration, upload verification or permission to switch clients. A durable creation marker makes a lost archive DB recovery-required, not an empty reset.

Archive acceptance: compare restored encrypted chunks with every original DB/media byte; preserve offsets, raw JSON whitespace, original IDs/times and drafts; prove plaintext/key denial; inject failure at manifest, chunk, file, source recheck and receipt boundaries; test missing files, malformed references, wrong hashes, symlink/outside reads, changed sources, lost key-write acknowledgment, missing DB/key, corruption, repeated copies and writer exclusion. Original sources stay byte-identical in successful/interrupted static fixtures. These local archive tests do not prove native vault/backup, paused-writer integration, actual mobile process kill or authorized legacy replay. Mapping into new observations requires separate original-owner/fence/receipt reconciliation.

Storage acceptance subcases: actual SQLCipher database and hot-journal bytes unreadable without the correct key; wrong/corrupt/missing keys never reset files; actual forced-process termination rolls back an uncommitted write; cross-process writer lock excludes the second writer; AES-GCM rejects ciphertext truncation/modification/substitution and authenticated metadata changes; each capture boundary restarts safely; account switch/lock/revoke never returns late plaintext/saved success. Local macOS runtime results, mocked vault/Auth tests, injected file interruptions and real mobile/OEM power-loss/backup tests are reported separately. Full J04 still requires observation binding and endpoint/UI integration.

Lifecycle acceptance: preparation failure or missing native root cannot enroll/open an account; a second runtime owner cannot prepare or enroll; failed or interrupted account changes invalidate old leases before awaiting Auth. An old capture must never save through a new account's lease. Verify background/inactive lock, no observer-triggered automatic resume authentication, exact saved-photo recovery by the original owner, explicit revoke retention and disposal while startup is pending. Test actual controller/DB refusal during preparation, unchanged Driver5 DB/draft/media bytes before legacy release, default-off behavior and unsupported-cohort rejection. Exercise actual DriverApi OTP/restore/refresh/sign-out paths with delayed HTTP and native token writes: late A cannot overwrite B or resurrect sign-out; failed B cannot reopen cached A by polling; storage failure precedes queue opening. Same-token polling must not re-enroll every10seconds, but background invalidation and Auth expiry defeat the cache. Expiry parsing is lock-only, not principal verification or offline authority. Test actual timer expiry and wrong/malformed Auth responses independently. Auth/vault/path mocks, local SQLCipher and real-device startup are separate evidence. Camera/background/offline continuation, fresh-install/iOS support, configured Auth and mobile migration remain open; backup packaging is not an OS restore test.
