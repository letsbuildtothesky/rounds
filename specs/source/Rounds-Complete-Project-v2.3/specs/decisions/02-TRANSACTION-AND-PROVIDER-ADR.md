## ADR-J01: bounded worker retry identity

For safe transient failures use five retry delays after the initial attempt: 5, 30, 120, 600 and 1800 seconds. Six failed attempts total enter recovery. Delays are measured from the failed attempt; no default random jitter. A valid Retry-After can lengthen the delay, never shorten it. Do not send if the next attempt would exceed the job deadline. Revoked/permanent failures need correction. Unknown or provider-accepted effects reconcile their original identity before any resend; this schedule does not apply to them. Lease is 60 seconds with heartbeat every 20 seconds. Synchronous derived state stays in its originating transaction, never in this retry loop.

Notifications dedupe on domain_event_id + recipient_id + channel + kind. Freeze the template on the first intent. Editing a template neither changes an existing intent nor creates a second effect. These values settle the conflicting E07/defaults/registry wording, not a business SLA.

## ADR-C01: one command metadata definition

COMMAND-CATALOG owns selected-root bindings, capability, transaction narrative, errors and emitted facts. OpenAPI owns typed request/result shapes; catalogue payload_contract must equal its referenced schema. Regenerate OpenAPI x-required-roots/x-errors/x-emitted-events, command Markdown and ERROR-BINDINGS together. Validate exact root identities and versions, not merely array length. Eleven stale x-required-roots mirrors were corrected in r1; retain a regression assertion for every command.

Reserved/historical state codes remain readable for migration. TR-327 through TR-330 (old pickup-remainder lifecycle) and TR-354 (pickup creating an extra open unit) are historical-only, not executable launch edges. No launch handler may traverse them. Existing abnormal quantities use explicit incident/return/disposition, not newly created residual deliveries.

## ADR-Q01: exact whole-order gate

The quantity contract supports positive values up to 1,000,000 in increments of 0.0001. Validate finite values/precision at the boundary and compare integer ten-thousandth quanta; never use epsilon to accept a short pickup. Resolve and lock selected orders and their current manifests before comparison. Reject duplicate/unknown selectors and duplicate/extra/missing lines; validate the full batch before any write. Every selected order must have preparation=ready and actual inbound/custody availability. PICKUP_NOT_READY is the stable preparation rejection; absent inbound receipt/discrepancy keeps its own typed error. Unequal full quantities return COMPLETE_ORDER_REQUIRED. Independent complete orders proceed only after explicit route/assignment adjustment.

## ADR-Q02: authenticated execution projection and first-snapshot preservation

Use GET /v1/queries/DriverRound with explicit view=execution and entity_id (Round), tenant_id and city_id. The existing default/full projection remains unchanged; the isolated increment does not implement it or fill its fields with placeholders. Execution view requires a verified bearer, ADR-A02 capability, current identity/device epoch, own-team membership/city capability, current acknowledged assignment and matching active whole-order claims. One pinned REPEATABLE READ transaction supplies a coherent bounded snapshot; permission rows are share-locked, pooled context is transaction-local, no provider request occurs under locks, and no domain/receipt/event rows are written. A permission/serialization/query failure returns no partial snapshot.

Scope is one local pickup plus unique complete-order dropoffs, at most1000 stops/lines and64KiB response. Reject unsupported/deferred inbound or route shapes explicitly. Return exact manifest quantities, preparation states, stop/unit identities, selected-root versions and each unit's immutable typed proof policy version/payload. Missing or invalid proof configuration is POLICY_NOT_CONFIGURED, never a sample default. Preparation is information, not a fabricated merchant receipt; ConfirmPickup still rechecks all physical/state/version rules.

For acknowledged team work, accepted_scope_hash is SHA256 of ADR-T02 canonical JSON with format=team_execution_v1, principal/tenant/city/Round, assignment ID/version, ordered stop/unit scope, unit proof policies and ordered complete-order manifest/line quantities/dropoff IDs. Exclude mutable state/preparation/version counters and fetch time. This is a team-authorized scope digest, not freelance commercial acceptance. Structural changes require explicit assignment reconciliation; the hash does not override any command fence/version check.

The native reader uses only the explicit registration API origin, bearer and current registered device, with no redirects, bounded body/deadline, generated exact-shape validation and cross-object identity checks. Validate principal/tenant/city/Round against the request before caching. Late account/query responses cannot become current. The online cache adapter preserves the first context's fetched time and expected versions for that assignment revision; a later fetch is not a predecessor receipt. A conflicting scope/policy invalidates the old revision and fails without rewriting it. A new revision invalidates prior Round contexts; invalidation is irreversible and old observations/photos remain readable to the original owner. Commands must resolve changed versions only from authenticated own-chain receipts under E05.

Acceptance includes registration→query→real pickup using query-produced selectors/versions/quantities; wrong tenant/city/job/device/revoked authority; absent proof policy; default-off Node routing; pool reset; native query→encrypted observation/photo→reopen, first-snapshot preservation, revision conflicts and late-response/account races. Provider verification/native HTTP use test doubles in their respective suites; this is not one deployed phone-to-server test. Full Driver work discovery/UI binding, native camera/offline continuation, result materialization/senders and configured Auth/device activation remain open. No legacy identifiers are converted into v2.3 authority.

Current execution and nested pickup contexts include the actual version of every selected delivery in expected_versions, from the same coherent query transaction. These versions do not enter the accepted scope hash. The new native reader accepts old snapshots with no delivery roots or new snapshots with all matching delivery roots; partial, duplicate and foreign roots fail. Never backfill an old encrypted context from a refreshed query. Selected-order issue capture without an original delivery version fails PICKUP_ISSUE_CONTEXT_UNAVAILABLE while prior queues/photos remain usable; a genuinely new authorized assignment revision can supply new authority. Round-only waiting reports require no guessed delivery version.

ADR-S08 stores the first pickup display and parcel selection in the encrypted working store for recovery; it never rebases a pending collection from a later query. No new schema, legacy conversion or phone activation.
