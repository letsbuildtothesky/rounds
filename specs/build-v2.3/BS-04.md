## Transaction invariants

One internal fulfillment unit per delivery, no child/residual units or separately assigned quantities. Preserve this identity for evidence/offline references; it is not a split-order product. Supplied V23 SQL is a backstop, not a complete handler. AUD-01/02/06 are reconciled in v2.3-r1; enforce ADR-Q01 and the exact typed error contract. ApprovePartialPickup authenticates/validates access then returns FEATURE_NOT_ENABLED with zero domain mutations for every authorised role, including owner. No feature flag or customer agreement can enable it.

ConfirmArrival is explicit driver observation, never automatic geofence completion. ConfirmPickup requires original execution fence, all selected manifests/units at one declared pickup context, actual receipt/preparation readiness and exact line-ID/quantity equality for every selected order. Missing/extra/duplicate/short/excess lines reject before custody/attempt writes. Batch is atomic. Five-required/three-ready cannot collect three; report shortage, keep D1 blocked, explicitly replan independent D2. Return no residual-unit/obligation IDs on successful pickup. Replay returns original result without another balance/event.

## Required identity chain

ConfirmPickup returns attempts indexed by unit ID. RecordHandoff references actual attempt, receiver/contact/place/instructions and quantities; server validates authorised unattended/alternate receiver rules and current custody. SubmitProof binds that handoff/attempt/policy to verified assets; CompleteDelivery takes attempt and proof_submission_id. Never reconstruct these IDs from UI index, current driver name or current version fetch. Physical handoff, local saved evidence, upload, verified proof and customer/Round completion are separate truthful states.

ReserveAsset issues purpose/size/hash-bound private upload permission; verify actual receipt/hash/ownership and scan relevant media before accepting proof. A timer/upload progress100 is not verified. Receiver change invalidates attributed signature, not unrelated valid photos. Retake preserves old valid image until replacement succeeds. Local capture may allow continuation only under explicit policy and with pending state; it cannot emit delivered.

## Exceptions and recovery

ReportIssue for recipient/address/package/cannot-complete/emergency opens a typed issue with real optional observations. It cannot itself move goods. ResolveIssue applies the permitted explicit decision, never forged driver proof. CreateReturn/ReceiveReturn and transfer request/receiver receipt use exact positive increments; replay adds zero, excess/wrong-manifest rejects. Decline/cancel transfer only before any receipt; partial physical return/transfer remains truthful and needs remaining disposition. This is not permission for a partial delivery route.

Implemented finite increment: [ADR-T07 handler](../../services/api/src/v23/report-local-pickup-issue.ts) and existing HTTP/CommandStatus accept original-fence own-team pre-pickup package/pickup_wait reports. Package reports hold only the selected order and block departure; waiting changes no readiness/preparation/receipt. Empty affected quantities assert no count. [Migration0006](../../services/api/migrations/v23/0006-issue-report-observation.sql) preserves immutable original actor/city/assignment/payload/manifest without backfilling old issues. [Report tests](../../services/api/test/v23/pickup-issue.postgis.ts) cover real restricted transactions/enrollment/HTTP, rollback, replay, authority, quantities, D1/D2 independence and prior-issue preservation. ADR-M04 adds [purpose-bound pickup photos](../../services/api/src/v23/pickup-issue-assets.ts), [immutable migration0007](../../services/api/migrations/v23/0007-pickup-issue-asset-binding.sql) and [actual byte/attachment tests](../../services/api/test/v23/pickup-issue-assets.postgis.ts). ReserveAsset requires the original pickup context and report time; VerifyAsset rechecks it after provider IO. Damaged/wrong reports require exactly one verified matching photo before writes. POD/foreign/unverified/other-observation attachments reject; missing/wait remains photo-free. ADR-S09 native capture/queue supports these purpose-bound photos and the staged G03 mutable form/camera/explicit report route. Draft saves or uploads never report a sent issue. ADR-T08's bounded wait/escalate handler is described below. Full source/phone acceptance, detail follow-up, physical decision/recovery branches and configured provider remain open. No shared migration or installed-client switch is implied.

Reschedule keeps delivery, prior attempts/promise/custody and obtains new admission as required. Before cancelling collected work, resolve all actual goods and accepted-scope compensation. Evidence disputes retain original proof and only authorised genuine replacement can restore validity.

ADR-Q04 [status query](../../services/api/src/v23/pickup-issue-query.ts) reads the original report plus a single current immutable decision chain under current same-driver/assignment/device/city authorization. [Reader tests](../../services/api/test/v23/pickup-issue-query.postgis.ts) use actual registration/report/query with explicitly seeded corruption/decision fixtures; ADR-T08 below separately exercises actual Operations writes into this query. The native current lease derives IDs from a validated committed report and never rewrites original versions/queue/evidence. [Native tests](../../apps/driver_harness/test/v23_pickup_issue_query_test.dart) cover encrypted reopen, identity binding, late responses and failures. Physical decision branches, approved host waiting/recovery presentation and configured phone activation remain integration work.

## UI/acceptance

The [pickup Action connection](W01-DISPATCH-PICKUP-ACTION-CHECKPOINT.md) must retain source card→detail semantics and recheck exact delivery/report IDs under identical fresh principal/session/tenant/city/date. A current `Action / issue` category alone never grants report or command access. Only direct non-resolved reports join; Round-only/foreign/name matches do not. A sole result opens review, multiple results require selection through existing list primitives. Never replace a saved reply for another report. Commit settlement refreshes the board but cannot clear whole-order holds or release a driver. Acceptance covers separate permission denial, stale/date change, blocked original assignment, preserved text/command bytes, one-POST status recovery and actual Driver instruction reads. No existing query/command or persisted schema changes are needed; broader physical decisions remain outside this connection.

Driver D03/D04,F01–F04,F08,I01,G01–G05 plus Dispatch delivery/issue/proof/return drawers use approved HTML and server allowed-actions. Never count an upload-only/debug camera screen as an implemented delivery journey.
