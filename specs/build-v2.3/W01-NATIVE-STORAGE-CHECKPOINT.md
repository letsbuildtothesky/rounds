## Concrete mapping required before conversion

New-work persistence shares the same SQLCipher writer and unchanged 14-table schema. ADR-S07 adds encrypted pod_transfer_v1 metadata and internal reservation/verification commands anchored to the source proof capture/committed handoff. Proof/completion derive IDs from original-chain receipts. Generic old captures remain unsupported without the explicit command_payload format; Driver5 data never passes through this API. No old row or file rewrite.

Android persistence finding: plugin10.3.1 uses asynchronous apply() for normal writes. The new [native disk barrier](../../apps/driver_harness/android/app/src/main/java/app/rounds/rounds_driver_harness/InstallationDurability.java), registered by MainActivity, commits only the new namespace's wrapped key/config/encrypted data on a background queue before Dart acknowledges a write. It accepts no secret or arbitrary path. [JVM tests](../../apps/driver_harness/android/app/src/test/java/app/rounds/rounds_driver_harness/InstallationDurabilityTest.java) compile the actual Java bridge against Android/Flutter and test five ordering/failure cases with mocked commit calls. The full ARM64 debug APK/Activity compiles with the bridge packaged. Actual bridge invocation, encrypted native disk/kill/full-disk and backup tests on a phone remain NOT_RUN; no phone installation.

The table above still defines required future semantic mappings into new account tables: none is implemented merely by copying an archive. Source IDs/bytes remain authoritative for recovery; no physical history, remote receipts or assignment fences are fabricated. Old secure session/owner markers remain untouched; proving original ownership and access to quarantined data is separate work.

[Encrypted-store tests](../../apps/driver_harness/test/v23_encrypted_work_store_test.dart) execute SQLCipher4.18.0/SQLite3.53.4 and AES-GCM on real temporary macOS files: plaintext/key denial, same-key reopen, modified/truncated/swapped ciphertext and altered-purpose rejection, four capture interruption points, replay conflict, missing-key/database/schema refusal, orphan preservation, single-writer lock, account switch/revoke/late-result invalidation, bounded immutable inputs and legacy-path noninterference. ROUNDS_V23_STORAGE_CHECKPOINT is an off-by-default debug-only diagnostic flag, not migration approval. It requires Android, an existing valid Driver5 DB and explicit HTTPS ROUNDS_V23_API_ORIGIN plus the configured Auth origin/key. It does not support new installs or pause a running old client. Startup errors abort before legacy UI/workers rather than inventing a recovery screen. Controller polling may re-verify online after resume, but camera returns/offline access have not switched. Do not enable on the user's phone until the named mobile/cohort checks and scope are approved.
