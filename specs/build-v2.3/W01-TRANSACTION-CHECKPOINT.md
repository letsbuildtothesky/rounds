## Evidence boundary

The [POD suite](../../services/api/test/v23/pod-assets.postgis.ts) extends real registered arrival/pickup/handoff execution into reservation and verification. The database, generated schemas, raster bytes/decoder and HTTP command handlers are real; Auth and object storage are explicit test doubles, not actual Supabase upload acceptance. Tests cover fresh secret-free replay/status, exact bytes/type/hash/truncation, wrong actor/tenant/city/purpose, revoked device or changed assignment during IO, receiver correction preserving photos, provider failure/corrupt sealed copy, SQL rollback and competing commands. The suite now continues through SubmitProof/CompleteDelivery: six reference kinds, exact note/location persistence, missing/foreign/invalidated proof, original scope denial, receiver correction, immutable history, replay after closure, competing IDs and completion rollback. Pending proof alone leaves delivery open. An unfinished order stays queryable with unchanged assignment digest; returns and pending commitments stay open. [Upgrade test](../../services/api/test/v23/proof-upgrade.postgis.ts) applies migration0005 to the previous proof column shape: every old field/state survives and new fields stay null. A test initially tried shortening a collected allocation; the existing IMMUTABLE_RECORD guard blocked it, and the test now verifies that protection. Initial revocation assertions expected UNAUTHENTICATED; the existing SQL device contract correctly returns NOT_AUTHORIZED, and those expectations were corrected. No access check was weakened.

The [arrival suite](../../services/api/test/v23/arrival-http.postgis.ts) exercises actual registered-device work query→pickup arrival→whole pickup→dropoff arrival→handoff through the complete restricted PostGIS fixture and HTTP handlers. Neither arrival in that chain is an admin state fixture. It verifies original scope, current-stop order, actual attempt ownership, timestamp causality, explicit GPS quality/route-wide policy overrides, stable replay/status, racing commands, pre-await identity and SQL/result rollback including the pending dropoff attempt. Arrival alone changes no custody/readiness/receipt/tracking/entrance state. Initial failures exposed unqualified PostGIS calls under the restricted search path and wrong preparation/query/location-table assumptions in test setup; fix explicit extension qualification and fixtures, not permissions or constraints. Auth/GPS are synthetic, not configured provider/phone evidence.

The [handoff suite](../../services/api/test/v23/handoff-http.postgis.ts) now exercises real registration/pickup/dropoff-arrival/handoff/HTTP. Its pickup-arrival setup remains labelled; the separate arrival suite covers that real predecessor. It covers single and competing-command races, exact decimal/multi-line custody, wrong/archived/cross-delivery contacts, unattended policy, missing/future/unsupported proof configuration, changed account/device/city/assignment, pre-await identity preservation and SQL/result-failure rollback. Assertions keep delivery open, evidence none, unit collected, claim active and Round active with no assets/proof submission or customer effect. Earlier tests caught an invalid archived_at predicate on immutable policy_versions and two invalid fixture mutations; these were corrected against the actual schema, not bypassed with role grants or disabled guards. This older suite stops at handoff; POD tests cover proof/completion. Server stale-retention/client connection remains open.

The native fixture executes actual PostgreSQL17.10 on a randomly selected loopback port with a restricted login. Five non-spatial source tables and selected source policies are real. Authorization and business mutations use clearly named v23_test probes, not the product's domain adapters. It does not use Supabase credentials, real orders, provider sends or a connected phone. Temporary test files are removed after shutdown.

Tests cover same-ID concurrency, changed identity, full rollback with retained rejection receipt, full-order guard rejection, exact root/fence helpers, forced deferred-constraint failure, injected serialization/deadlock SQLSTATE retries/exhaustion, lost COMMIT acknowledgement, current-access revocation, same-actor cross-tenant and cross-city reads/writes, pool context reset and superuser refusal. PostgreSQL actually executes and commits/rolls back; injected transport and SQLSTATE failures are labelled. These tests do not prove the complete pickup workflow or all197 acceptance cases.

The separate full-schema suite executes PostgreSQL17.11 and PostGIS3.5.6. The earlier20tests cover actual tenant FK/RLS, non-owner/non-broker roles, whole-order allocation, valid atomic revision, seals and labelled transaction probes. The new [local pickup suite](../../services/api/test/v23/confirm-local-pickup.postgis.ts) executes the actual handler against all131tables: complete pickup, exact decimals, atomic multi-order selection, partial rejection, stable attempts, duplicate race/replay, wrong/stale roots, original assignment, revoked scope, suspension before new pickup and replay, inbound/history bypass prevention and rollback after physical writes. Existing live attempts cannot be duplicated even if inconsistent stored state leaves a unit open; the original attempt is preserved and pickup rejects. Counts and exact passing scope are in the fingerprinted report, not inferred from test filenames. No provider sends or physical receipt/custody is invented by fixture planning.

The [HTTP/PostGIS suite](../../services/api/test/v23/pickup-http.postgis.ts) adds actual localhost requests and real restricted-role principal/device/job/receipt checks: commit/status/replay, retained business rejection, forged credentials/actor, expiry, disabled principal, revoked membership/device/city, epoch change, reassignment, cross-tenant access, missing/legacy receipts, connection reuse, body/origin bounds and default-off routing. It also tests that the API cannot assume the resolver role or read private identity columns. [Device/Auth unit tests](../../services/api/test/v23/device-session.test.ts) exercise the actual Supabase getUser client against mock provider responses. That older database suite seeds its device credentials; the new [registration suite](../../services/api/test/v23/device-registration.postgis.ts) obtains credentials through the actual registration service, then runs pickup/status and self-revocation. It covers concurrent duplicate enrollment, expiry renewal, account separation, immutable platform/key, archived identity, rate admission, audit rollback and lost COMMIT acknowledgement. Auth verification is still mocked in both suites. No configured Supabase Auth, native enrollment/storage, Realtime or production ingress acceptance is implied.

Run `ROUNDS_TEST_PG_BIN=/absolute/postgresql17/bin npm run test:postgis --workspace @rounds/api` with PostgreSQL17 plus PostGIS installed. The directory is a tool location, not a target database. Missing configuration fails this suite; it is never silently skipped. Set the same variable for `tools/verify_v23_checkpoint.py` to include it in fingerprinted evidence. No external database URL is accepted by the fixture.

See [fingerprinted test report](generated/test-results.json) and its run logs. Existing API regression tests preserve legacy behavior and do not certify v2.3 compliance. AC-01/03/05/07 remain full-application NOT_EXECUTED despite these lower-level cases passing.

Neither planning nor preparation creates a receipt or custody movement. No global product feature was removed. See P05 and ADR-T03 for batch result identities and this narrow boundary.
