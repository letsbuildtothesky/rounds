## Required controls

The [POD provider checkpoint](W01-POD-PROVIDER-CHECKPOINT.md) implements short-lived exact-byte grants, private-bucket metadata checks, create-only/reread semantics, bounded provider IO and application query redaction. Configured Storage RLS, edge/access-log redaction, privileged key isolation/rotation and retention/restore must be independently verified; code/metadata are not policy certification.

Restricted transaction role with forced scoped RLS, same-tenant references, validated principal/city/job context and independent migration/broker/notifications/entitlement/retention roles. Recheck list/detail/export/media/realtime authorization, not only button visibility. Driver devices and auth identity columns never enter dispatcher projections. Subscribe through finite private topic grants bound to current entitlement; active-session revocation needs actual Supabase test, not merely SQL or TTL assertion.

Private purpose-specific assets with server-generated keys, bounded MIME/size/hash, quarantine/scanning where relevant and expiring access capabilities. POD, messages, import/export and identity/face evidence have distinct policies. Never log signed URLs/content/addresses/bank details or commit service secrets. Imported prototype public-token shapes require provenance/restriction review before publication; original credentials are not production defaults.

Approved retention matrix per data class/purpose/subject/hold is a launch requirement; absent policy is not indefinite retention. GPS expiry snapshots remain bounded, current-position and raw-history rights separate. Privileged purge serializes with holds, records immutable count audit and dedupes run identity. No ordinary API or dispatcher can impersonate retention role. Legal/country periods require owner/privacy review; this build plan does not certify compliance.

## Evidence suite

Test two tenants/two cities with identical display names, revoked membership/current job, wrong receiver/driver, forgery of tenant/header/expected roots, cross-purpose media, signed webhook replay, unsafe notes/files and CSV formula injection. Test raw GPS holds/purge race, off-duty exact-location denial, current position without allowed raw history, device/account switch and expired grants. Threat tests run against actual restricted roles, not superuser fixtures.

Keep source acceptance IDs and concrete AC-cases mapped to test code, fixture, command/event trace, CI run, screenshots and device build. Proposed latency/load/RPO/RTO targets remain proposals until approved and measured. Report p50/p95/p99, error/freshness/queue lag, database connections/IO, egress/cost and mobile incremental battery; no inferred1,000-driver capacity from sample maps.

## Recovery and rollout

Database restore and private object restore are both tested. Preserve command/event/effect receipts so restore cannot repeat notifications, commerce writeback or settlement records. Primary outage yields readonly labelled Dispatch cache while Driver durably captures authorised work. After recovery refetch/reconcile before sending stale proposals or external effects. Trace command→transaction→event→outbox→provider receipt→projection using safe IDs.

Cutover follows MIGRATION-AND-REUSE: source mapping, backup/restore, one writer/cohort, compatibility/unknown-client plan and reviewed forward repair. No destructive SQL or deletion without explicit scope and recoverability. Never push fixtures to real recipients/providers. Release exit requires closed critical findings, signed source baseline, generated-client compile, schema/RLS/concurrency, full relevant journeys, visual/device/provider evidence, monitoring, recovery runbook and explicit promotion. Unfinished later modules remain in the ledger, not disappeared from “complete”.
