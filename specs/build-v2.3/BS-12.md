## Reference and state inventory

Use exact source SHA/path from generated/driver-screens.json and ui-controls-static.json.47 is a file count, not a complete state count. Static markup inventory does not include every script-generated row/menu/state. Before implementing each selected feature, render and exercise its approved HTML and enumerate default, selected, disabled, expanded sheet, pending, empty, error, stale, revoked, offline, retry and superseded variants actually required by its contract. Outer review/sample controls are not app controls. Missing states become named design gaps; approve a component-based solution rather than silently improvising.

For each state record: reference file/hash, viewport, device scale/text scale, locale, fixture IDs/content, entry route, permitted actors, actual component, query, command+payload IDs, expected state/events, recovery/back/dismiss and screenshot paths. Use approved drawers, not default dropdowns where none exists in the source.

## Measurement contract

For Driver comparisons render the **inner phone app surface**, excluding presentation frame/mock OS chrome, at393×852 logical units and responsive320/360 widths/short heights/enlarged text. One reference CSS pixel maps to one Flutter logical pixel at equal content viewport; physical pixels equal logical pixels×devicePixelRatio. Don't multiply all fonts/padding by screen-width ratio or screenshot width. Flexible map/scroll regions absorb available height; preserve safe areas once, never double-padding OS status/navigation bars.

Measure box geometry, padding/gaps, radius, line-height/baselines, font family/weight and icon artwork separately from tap target. Reference tokens supply 18px inset, 4/8/12/16/20/24/32 rhythm and52/60/64/68 targets where that specific screen uses them; later screen CSS/notes can legitimately differ. Driver Arial/Helvetica metrics need a licensed available matching font or explicitly approved substitution measured on device; Dispatch's Inter stack is independent. No font licensed use is assumed by writing its name.

React ports final effective DOM/CSS layout rules, not just first stylesheet declarations in a prototype with later overrides. Flutter shared primitives should implement matching constraints/flex/scroll, not a webview pasted over core app. Map-provider internals may limit exact custom styling; document a platform constraint for approval instead of silently moving the dock.

## Capture/compare gate

Use identical content/state/date/viewport for source and app. Store reference, actual and diff/overlay with source/app hashes. Inspect typography, top/bottom spacing, wrapping, panel/map proportion, buttons, icons and modal behaviour. Any masking must be predefined and limited to nondeterministic provider imagery/OS clock; never mask the whole map controls, dock, text or failed region. Proposed geometry tolerance≤1 logical pixel for fixed app-owned geometry at standard viewport; typography/anti-aliasing assessed separately. Reviewer must approve thresholds/font substitutions; no fabricated universal percent-diff PASS.

Dispatch matrix:1366×768,1180×820,1024×768,820×1180,768×1024 plus reference-specific cases. Keep primary navigation, sticky timeline labels and local scroll; no document-wide overflow. Test mouse/touch/keyboard, focus trap/return, Escape/back/swipe, reduced motion, long names, keyboard resize, safe areas and screen readers. Every action must reach actual permitted handler/result and surviving recovery state.
