Version 1.0 · 2026-09-08 · Active implementation contract; readiness is scoped below. Sources P09/E07/E08 and event-consumer registry. R1 recovery core; R2 complete communications.

## Changelog

- 1.0 (2026-09-08): reconcile v2.3-r1 rules, ground retain/adapt/replace work in baseline code, and separate implementation readiness from acceptance and release gates.

## Conversations and media

Replace stop/name-keyed assumptions with authorised job/relationship conversation identities. OpenConversation resolves exact participants and context; SendMessage preserves client ID and immutable retry payload. Store message+attachment refs+event/outbox atomically only after permission/type/size/purpose checks. Use real private ReserveAsset/VerifyAsset receipts; staged draft media remains local until explicit Send. Proposed10×20MB is a reviewed configurable ceiling, not a guarantee of supported provider formats.

Retain per-thread draft, staged attachments, unread cursor and minimised/closed UI state. Late camera/mic/file permission callbacks cannot attach to another/new conversation. Stop capture/record streams on cancel/leave/background. Failed retake/replacement leaves earlier valid media. Location sharing is an explicit action with observation time/source; no auto-send of current GPS. Render human text safely, preserve provenance of system events/manual call logs and redact sensitive content from telemetry/logs.

## Actual calls and notifications

Start/RespondCall/log outcomes use provider adapter receipts or visibly manual dialer outcome. Dialer launch, timer or sample connected state never proves a call. Incoming caller/job context, answer/decline/busy/missed/reconnect states require approved design and provider/native tests before enabling VoIP. Voice notes can work without a VoIP provider and must not be hidden merely because calling is gated.

Notifications derive from committed facts for eligible recipient. Mark read is separate from acknowledging change/accepting offer. Tap refetches current authorised entity, including superseded/expired/revoked/offline cases. Dedupe identity is event+recipient+channel+kind; template is frozen at enqueue, not retry identity. Use reconciled ADR-J01 for the notification identity and safe retry schedule.

## Worker mechanics

Add `services/worker` with typed handlers for all durable actions in generated/service-actions.json. Keep derive/internal entries inside originating transactions. Relay transactional outbox with unique consumer/effect receipt. Claim lease, heartbeat, recheck deadline/current scope, perform external call only after commit, record receipt then ack/archive. Crash after provider accepts must reconcile original effect identity, not send again. Dead letters/unknowns are inspectable with safe retry; manual retry preserves identity until uncertainty resolved. Registry defaults are settled by ADR-J01; offer deadlines always override generic retry delay.

## UI/acceptance

Phase39 ordinary driver click opens contact actions, one expanded chat plus minimised tray; Driver H01/H02/H03/M01 use approved references. Background replies update unread without stealing focus; opening delivery does not silently retarget draft. Tablet overlay retains useful map/context.

Run all P09/E07 cases plus AC-08. Switch two same-named drivers, stage media, receive reply, change city then send: exactly one original participant/thread receives it. Permission revocation blocks media access/send. Retry read/send/push after response loss and template edit yields one logical message/effect. Crash worker after external acceptance; no duplicate. No real recipients are used by fixture tests. Incoming/missed calls and provider fallback remain gated until actually exercised.
