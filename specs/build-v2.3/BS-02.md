## Intake implementation

Current bounded implementation: [manual intake checkpoint](W01-MANUAL-INTAKE-CHECKPOINT.md). SaveDeliveryDraft uses exact original command identity and current deliveries.create city authority, persists each manual submission and invalidates dependent review on edit. ADR-Q08 adds an explicit Workspace manual context/current revision and a login/tab-bound browser controller. The source-derived React form opens through the staged board plus control, retains edits and recovers original saves. ADR-T10 implements ReviewAddress under separate deliveries.review with current hash/version and immutable before/proposed/selected history, preserving all unrelated draft fields and old revisions. Address review alone remains review_needed and never confirms an entrance or goods. It neither invokes the legacy create RPC nor creates a delivery. Original HTML is unchanged; source pixel parity and interim status/recovery review remain unaccepted. Binding the approved map-review control, timing/slot admission and whole-order commit are next, not marked implemented.

Reuse existing delivery-form validation/UI mechanics only after mapping to intake_batches/intake_drafts/address_suggestions and immutable source revisions. Manual Add Delivery is always first-class. SaveDeliveryDraft creates no delivery/custody; ExtractDraft queues bounded source processing and returns operation identity. AI/provider choice remains gated, untrusted source text is data, late input-hash callbacks cannot alter a newer draft. Keep original Thai/English text, recipient versus buyer and field provenance.

ReviewAddress explicitly accepts/edits/rejects operational corrections; formatting normalization alone is not a fake geographic verification. CommitDelivery locks current draft/version, verified source identity and slot reservation, consumes valid hold, creates delivery/manifest plus exactly one whole-order internal unit, and returns exact IDs. Source connection+external order key dedupes; fuzzy names only suggest duplicates. CommitIntakeBatch has explicit per-row results; retry only unchanged unresolved rows, never replay committed rows as new orders.

## Calendar transactions

Resolve one rule: site+brand → site → brand → city; equal-specificity ambiguity rejects. Materialization locks logical template/date before switching current occurrence pointer; count live reservations across old/new versions so revision change cannot reset capacity. Store actual UTC promise instants with service date/timezone and original offsets. No machine-local date arithmetic. Overnight and DST ambiguity cases are required even when pilot is Bangkok.

HoldSlot uses server clock under admission lock. Refresh extends same live hold within approved lifetime, never revives expired history. MoveSlotHold locks both logical keys and commits target/source changes atomically. Delivery conversion changes draft→delivery linkage once. Reduced cap below commitments preserves bookings, flags overcommit and blocks further admission. Template/override edits affect new admission unless explicit versioned promise change is applied. Direct windows remain available where configured. A slot admission is not a vehicle-capacity guarantee or permission to broadcast.

Keep readable before/after address facts, stale-source review, row-level failures, limits and unsaved-draft safeguards. No sample address/release buttons in production. ## Acceptance

All P02/P03 ledger cases; AC-02/09. Last-capacity concurrent holds yield one winner. Expired hold commit resolves previous command before readmission. Move to full target leaves source intact. Reducing10→6 with8 commitments retains8 and prevents new booking. Old source update and late extraction cannot overwrite approved address. Replayed commit yields same delivery/unit. CSV quoting/BOM/newline/formula cases and mixed-success batch have deterministic per-row outcomes. No delivery quantity split appears in intake, planning selectors or any override.
