## Local architecture

Issue connection: [pickup_issue_store.dart](../../apps/driver_harness/lib/src/v23/pickup_issue_store.dart) freezes explicit package/wait observations from the authorized pickup snapshot; the existing materializer and transport send ReportIssue and recover its original status. Selected delivery/unit/manifest/quantities join the snapshot and require the FIRST delivery version. Optional arrival/earlier-issue receipts supply only their own changes; waiting/held roots need not increment. [Basic tests](../../apps/driver_harness/test/v23_pickup_issue_test.dart) cover encrypted rows, exact requests and scope/quantity/receipt handling. [Pickup photo adapter](../../apps/driver_harness/lib/src/v23/pickup_photo_transfer_store.dart) derives purpose only from the original selected order/report; the shared camera/Auth/uploader handles encrypted bytes, status and retries. [Photo tests](../../apps/driver_harness/test/v23_pickup_photo_test.dart) exercise actual SQLCipher/files, TypeScript validation, interruption, rollback, purpose/binding tampering and preserved evidence, with labelled Auth/camera/HTTP doubles. Missing/wait remain photo-free; damaged/wrong require exactly one verified photo. G03 mutable editing/preview and a staged route now exist as described below; actual Operations decisions, host recovery and installed phone remain open. No legacy data or pending bytes are rewritten.

G03 editing boundary: [pickup_issue_form_store.dart](../../apps/driver_harness/lib/src/v23/pickup_issue_form_store.dart) stores pickup_issue_form_v1 in existing encrypted work_cache, with original execution/display context, selected order, stable report ID and editable reason/details. Each camera attempt has a distinct asset/capture ID in the existing one-pending-intent mechanism; candidate bytes are encrypted before selection changes. Cancel/failure retains previous selection and all old bytes. A changed reason clears selection, not evidence. Only explicit submission freezes the latest durable text and selected candidate/time; retries reuse the frozen draft. Empty optional details are omitted and nonempty details remain exact, bounded to 240 Unicode scalars. A private provenance-checked binding attaches the selected stored image without recapture, relabelling or copying; public arbitrary-asset adoption stays forbidden. Reopen handles interrupted file/selection/freeze boundaries. The controller awaits edits, stops on failed saves, suppresses late account/dispose results and uses existing reserve/PUT/verify/report transports. Its staged route delegates actual report/recovery/contact destinations; it is not main/phone activation.

Current bounded implementation: [native checkpoint](W01-NATIVE-STORAGE-CHECKPOINT.md). Registration, SQLCipher/AES-GCM, legacy preservation, startup/Auth, execution context, camera return and the linear execution queue exist. ADR-S07 extends one saved delivery photo through reservation, signed PUT, VerifyAsset, SubmitProof and CompleteDelivery. Original assignment/own receipt bindings and exact retry identity remain enforced. No legacy screen starts this sender; configured provider/mobile/visual activation remains open.

Replace final-command-first coordination with an encrypted observation store, binding resolver, command materializer, sender/reconciler and asset uploader. ADR-S02 pins sqlite3 3.5.2 SQLCipher and cryptography 2.9.0 AES-GCM; native platform/backup tests remain required. flutter_secure_storage holding a key does not prove database/file encryption. Use the14-table clean reference as model, not a drop-in upgrade script for current app version.

Before offline use cache authorised assignment ID/version/scope, unit/stop identities and policy. Each immutable observation records principal/device/session, original time/fence, action data, evidence refs and predecessor observation IDs. Persist private file and DB metadata durably before showing saved; staged paths/checksums/orphan recovery handle crashes. Do not invent previously unseen work offline.

## Binding and materialization

ADR-S09 pickup-photo transfers use the existing pod_transfer_v1 record with explicit photo_kind=issue_photo and no handoff anchor. Schema forbids self-dependency rows, so exact internal receipt pointers/values/command IDs are kept in that encrypted transfer record with actual command_dependencies. Persist the ReportIssue binding atomically with its command/link; reconstruct the reservation, verification and report references on read. Do not invent a physical predecessor or weaken the local schema. Existing POD records/observation_bindings remain unchanged. No field migration/backfill or phone cutover is needed for this staged adapter; dependencies are ADR-M04, S05/S07, registered current account/context and an explicitly configured upload origin.

The local observation storage portion remains [offline_observation_store.dart](../../apps/driver_harness/lib/src/v23/offline_observation_store.dart). ADR-S07 extends explicit command_payload envelopes for proof/completion without rewriting old observations. A proof photo uses local_asset_id, never caller-supplied remote asset_id; handoff/policy/attempt/location IDs derive from the original committed chain. One handoff predecessor, one saved photo and one pending proof candidate are supported. Signatures, multiple-photo/candidate/branched workflows and general files remain separate adapters.

Resolve only from authenticated committed predecessor receipts/GetCommandStatus. Pickup result selects attempt by fulfillment_unit_id, never array position. Arrival receipt supplies own changed stop/attempt versions. Handoff result supplies handoff_id; VerifyAsset supplies verified asset; proof result supplies proof_submission_id. Store predecessor ID, exact source JSON pointer, target payload pointer, value and receipt command ID in observation_bindings.

When all dependencies resolve, atomically allocate/persist command ID, exact bytes/hash, expected_versions and original execution_fence. Never mutate frozen request on retry. Merge only own predecessor versions, never refresh original assignment authority from a new GetDriverRound. Sender respects dependency readiness, retry due time and principal authentication, not merely timestamp sort.

Unknown response blocks successors and queries original command. Committed result releases bindings; rejected/retained result does not. If original assignment changed, retain genuine assets/observations under RetainOfflineObservations with incident receipt and no current-work mutation. Same driver reassigned is still a changed fence. Local retained state is not delivered and cannot produce synthetic success events.

## Media transfer connection

The server side is now implemented in [the provider checkpoint](W01-POD-PROVIDER-CHECKPOINT.md): a four-minute Rounds signed-PUT target backed by private create-only Supabase objects. This matches the native no-extra-token protocol without changing old data or UI. Default origin allowlist/provider selection remain empty/disabled; actual TLS/provider/phone and mapped migration acceptance are still required.

[Photo transfer store](../../apps/driver_harness/lib/src/v23/photo_transfer_store.dart) owns a versioned pod_transfer_v1 record in existing encrypted work_cache plus pending_commands, command_dependencies, upload_sessions and observation_bindings. ReserveAsset/VerifyAsset are internal transfer commands, not invented physical observations. Their provenance is the source proof capture and its committed handoff; resolved_by_command_id identifies the actual receipt, while the dependency observation anchors the original handoff. No schema migration, local capture mutation, generic note conversion or plaintext temporary file. Local_assets remains saved/local integrity; transfer verified means a validated remote VerifyAsset receipt, not delivery completion.

Only raw signed PUT to explicitly allowlisted HTTPS origins is implemented; the default allowlist is empty. Token-bearing/POST/resumable/general file protocols fail closed pending their adapter. Capabilities stay in memory, redirects and app credentials to the upload host are prohibited, and storage lock aborts the request. Before PUT, persist uncertainty; after a lost PUT response attempt server verification first. Only a missing original verification status permits another PUT with a fresh capability and the same reserve/verify command IDs. Server sealing/hash/ownership verification remains authoritative. Photos are never deleted.

## Security/lifecycle and UI

ADR-S05's [capture hand-off](../../apps/driver_harness/lib/src/v23/driver_storage_auth.dart) persists a [camera intent](../../apps/driver_harness/lib/src/v23/camera_capture_store.dart) before launch and re-verifies the same owner on foreground return. It does not keep the store unlocked in the background. A returned image completes only that original intent; an invalidated assignment permits local retention, not new commands. Cancellation/error never removes an older photo. Lost acknowledgment uses exact IDs/bytes; unresolved capture blocks relaunch. No automatic ImagePicker lost-data adoption, legacy draft dual-write, source-file deletion or inferred verified proof. G03 now has a staged form/preview route; host recovery, temporary camera-source recovery and offline policy remain required before mobile cutover.

Separate per-principal keys/storage and encrypted local bytes. Sign-out/auth-expiry preserves pending evidence but makes it inaccessible to another account; re-auth original owner before upload. Clear only after verified server receipt plus allowed retention. Device revocation stops new server access without silently erasing incident evidence. Migration of old pending items follows MIGRATION-AND-REUSE and quarantines unprovable fences.

N02 shows recorded locally/uploading/service-verified/retained-for-review/failed states and recovery actions. Connectivity is independent of GPS N03 and permissions N01. An empty queue is not proof of upload if orphan files remain. Work-home and History reflect pending evidence, not fake finished work.
