Generate models and validators from the corrected OpenAPI/event/policy contracts. `generated/commands.json` maps every command to owner, payload/result schema, expected roots, errors and emitted facts. Read-only snapshots have stable filter-bound keyset cursors/as_of; results never expose table-wide select-all, secrets or another tenant's work.

## Shared handler algorithm

1. Bound and parse request; authenticate and resolve current principal/capability/tenant/city from trusted credentials. Validate exact envelope, payload and root identities, not just version-array length. Retain original occurred_at as evidence.
2. Canonicalize the validated request deterministically, preserving original command ID and physical execution fence. Define canonical-number/Unicode/hash rules in contract tests before using hashes as dedupe. Same ID/different bytes yields IDEMPOTENCY_CONFLICT; never generate a replacement ID in a server handler.
3. Acquire one pinned PostgreSQL connection; BEGIN; SET LOCAL trusted scope under a non-owner, non-BYPASSRLS role. Lock the command receipt, admission keys, delivery IDs, unit claims, Round/trip/broadcast/offer roots, manifest/line balances, then global driver/vehicle guards; sort within each class. Newly discovered dependency roots must follow the same order or restart safely.
4. Validate expected versions, ownership, state and cross-row physical/consent predicates inside the transaction. State+derived gates+facts+outbox+sanitized receipt commit together. No provider call under database locks. Rejection leaves no partial operational mutation. Distinguish retained observation outcome from success/rejection.
5. COMMIT before response. Serialization/deadlock retry preserves identity with bounded attempts. Lost response uses GetCommandStatus; async accepted intent is202, not fulfilled work. External effects run from durable outbox with original effect identity.

Migration/worker/auth roles remain separate. Auth/Storage admin credentials are not core mutation credentials. Cross-tenant matching uses a narrow broker, returning only eligible facts/conflict booleans. Clear context through transaction-local settings and test connection reuse across tenants. Receipt read/replay requires original tenant/city, actor and current authorization. ADR-T02 fixes identity/savepoint/retry rules; ADR-A01 defines the isolated HTTP identity/device and immutable original-job receipt boundary; ADR-A02 defines explicit authenticated installation registration/renewal/self-revocation. The [checkpoint](W01-TRANSACTION-CHECKPOINT.md) records pg8.23.0, actual registration→pickup/recovery and HTTP/PostGIS tests. Configured Auth, native device secret storage, all-business-role/handler coverage and clients remain open; passing local tests do not authorize activation.
